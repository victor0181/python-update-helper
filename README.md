# Python 更新助手

一键把本机的 Python 环境收拾干净：**自动发现所有解释器 → 测速挑出最快的国内 pip 镜像 → 写入 `pip.ini` → 升级 pip → 导出已装库清单**。

纯标准库实现，**零第三方依赖**，Python 3.7 及以上均可运行。双击一次就完事，不想装任何东西的时候特别省心。

---

## 它解决什么问题

国内直连 `pypi.org` 往往慢到让人放弃安装。手动换源又要逐个解释器改配置文件，virtualenv、conda 环境、多个 Python 版本一多就容易漏。

这个工具把这件事做成幂等的：跑一次，本机每个 Python 都被配好镜像源；再跑一次，结果完全一致，不会叠加、不会污染配置。

## 特性

| 能力 | 说明 |
| --- | --- |
| **自动发现** | 扫描 PATH、Windows 注册表、常见安装目录、virtualenv / conda 环境，并行探测，不逐个卡顿 |
| **镜像测速** | 对清华 TUNA、阿里云、腾讯云、中科大逐个实测延迟，选最快的当主源 |
| **安全改写** | 按行改写 `pip.ini`，保留注释、键名大小写、键顺序、空行、编码；写前自动备份 |
| **升级 pip** | 对每个解释器分别升级，单台失败不影响其它 |
| **导出清单** | 汇总各解释器的已安装库，导出带时间戳的 txt 报告 |
| **图形界面** | 可选 GUI，勾选要处理的解释器，默认不勾选工具自身依赖的那个 |
| **可回退** | `--restore` 一键改回官方 PyPI |

## 快速开始

### 方式一：双击

双击 `一键配置.bat`。它会自动挑一个可用的解释器，优先以无控制台窗口的方式打开图形界面。

> `.bat` 被**刻意**写成纯 ASCII + CRLF。所有中文文案都在 `.py` 里，这不是疏忽——`cmd.exe` 按当前代码页逐字节读取批处理文件，混入非 ASCII 会让行边界错位并报「不是内部或外部命令」。

### 方式二：命令行

```bash
python pip_helper.py                 # 配镜像源 + 升级 pip + 列出已装库
python pip_helper.py --list-only     # 只看清单，绝不改动任何配置
python pip_helper.py --dry-run       # 预览将要做什么，零写入
python pip_helper.py --restore       # 把 pip 源改回官方 PyPI
python pip_helper.py --help          # 查看全部参数
```

命令行版是能力的**唯一真源**，GUI 只是它的前端——不存在「只有图形界面才能做到」的操作。

## 命令行参数

| 参数 | 作用 |
| --- | --- |
| `-p, --python 路径` | 指定要处理的解释器，可重复使用 |
| `--exclude 关键词` | 排除路径中含该关键词的环境，可重复使用 |
| `--mirror 名称` | 手动指定镜像，跳过测速 |
| `--no-probe` | 不测速，直接用预设顺序里的第一个 |
| `--list-only` | 只列出已装库，不改配置、不升级 pip |
| `--no-upgrade` | 只配源和列库，不升级 pip |
| `--no-config` | 不动 pip 源配置 |
| `--no-export` | 不导出清单文件 |
| `--restore` | 把 pip 源改回官方 PyPI |
| `--configure-only` | 只做配置这一步 |
| `--upgrade-only` | 只做升级这一步 |
| `--probe-only` | 只做镜像测速 |
| `--config-file 路径` | 指定要改写的配置文件 |
| `--trusted` | 附加写入 trusted-host |
| `--dry-run` | 只预览将要做什么，不实际修改 |

## 安全保证

改配置这件事最容易出岔子，所以这里的规矩是硬的：

- **只写一个主源**，不写 `extra-index-url`；用户自己的私有源会被保留，本工具以前写进去的镜像值会被清掉。
- **按行改写**，保留注释、键名大小写、键顺序、空行，以及 CRLF / BOM / GBK 编码与文件里的其它段落。
- **先备份**成 `pip.ini.bak-时间戳`，再以「临时文件 + 原子替换」落盘。
- **每一步独立 `try/except`**，某台解释器出问题不影响其它解释器。
- `--dry-run` 与 `--list-only` 保证零写入，可以用来先看清楚将要发生什么。

Windows 上的 `pip.ini` 位置取自各解释器自己的 `pip config debug`，因此 virtualenv 内部的独立配置也能被正确定位。

## 系统要求

- **Windows**（主要目标平台；核心逻辑跨平台，但注册表探测与无窗口启动是针对 Windows 的）
- **Python 3.7+**，仅需标准库
- 图形界面需要 `tkinter`（官方安装包自带；部分精简发行版可能缺少）

## 目录结构

```
Python更新助手/
├── 一键配置.bat        # 双击入口（纯 ASCII + CRLF）
├── pip_helper.py       # 命令行版，唯一真源
├── pip_helper_gui.py   # 图形界面，薄前端
├── 清单/                # 导出的已装库清单（运行时生成，不入库）
├── .gitattributes      # 钉死换行符：.bat=CRLF，.py=LF
└── .gitignore
```

## 已知情况

- 清华 TUNA 在部分网络环境下测速可能返回 `403`（阿里云正常），疑似网络侧 WAF，与本工具无关。若全部镜像都测不通，会退回预设顺序（清华优先），不会中断执行。
- 发现阶段的耗时主要花在**逐个启动 Python 进程**（每次约 0.5~1.6 秒），已改为并行探测以缩短等待。
- 若把工具放在盘符下一级目录（例如 `D:\pip助手`），向上遍历时会碰到盘符根目录，已跳过不遍历。
